1. What you are looking at

This is a modern Next.js App Router project using TypeScript. The architecture separates UI routes, reusable features, shared components, and static data into distinct folders.

@/ is a shortcut for src/. So import { HERO_SLIDES } from "@/data/hero" means src/data/hero.ts.

Server components (default)

Files in src/app/ without "use client" render on the server. They are fast, great for SEO, and combine smaller feature components to build the page.

Client components

Files starting with "use client" (like the Navbar, Swipers, Framer Motion animations) run in the browser to handle interactivity, clicks, and state.

3. The page shell (every URL)

Next.js wraps every page in src/app/layout.tsx. This is where the global fonts (Geist), global CSS, and the main Navbar/Footer are injected.

1. Metadata & Fonts Sets up SEO headers and loads Geist and Geist_Mono fonts.
2. Global CSS Imports globals.css which brings in Tailwind CSS v4.
3. Page Wrapper Renders the <body>, the Navbar (if placed here or inside pages), the {children} (page content), and the Footer.

4. Homepage — how it is built

File: src/app/page.tsx. It is extremely clean. It simply imports feature sections dynamically and stacks them.

import dynamic from "next/dynamic";
import Navbar from "@/components/layout/Navbar/navbar";
import Hero from "@/features/Hero/hero";

// Lazy-loaded to improve initial page load speed
const Services = dynamic(() => import("@/features/Services/services"), { ... });
const Startups = dynamic(() => import("@/features/Startups/startups"), { ... });

export default function Home() {
  return (
    <>
      <Navbar />
      <Hero />
      <Services />
      <Startups />
      <Products />
      <HowItWorks />
      <Partners />
      <NewsInsights />
      <Customers />
      <Verticals />
      <Footer />
    </>
  );
}

5. Navbar & Mobile Menu

File: src/components/layout/Navbar/navbar.tsx.

Client Component Uses "use client" because it needs state to track scroll position and mobile menu open/close events.
Desktop vs Mobile Dynamically imports DesktopNav for large screens, and uses Shadcn's Drawer for the mobile off-canvas menu.
Data-Driven The links and mega-menus are generated by mapping over NAV imported from src/data/navigation.ts.

6. CSS — how styling works

Instead of old CSS files, this project uses Tailwind CSS v4 and CSS variables.

FileRole
src/app/globals.cssThe brain of styling. Contains @import "tailwindcss", Shadcn UI base colors, DaisyUI plugin, and custom animations like marquee and fade-in.
Tailwind ClassesInside .tsx files, you'll see classes like bg-[#031B3D] text-white sm:py-20. This replaces the need for separate CSS files.

Note: Animations like Framer Motion (motion.div) are also heavily used directly in components (e.g. Universities.tsx) for scroll effects.

7. Data — where content lives

To avoid hardcoding text inside UI components, content is stored as TypeScript objects in src/data/.

// Example from src/data/hero.ts
export const HERO_SLIDES = [
  {
    id: "what-if",
    eyebrow: "What If",
    title: "Your Business",
    highlight: "Could Do More?",
    description: "Modernize legacy systems...",
    video: "/videos/hero-bg3-hero.avif",
    webmVideo: "/videos/hero-bg3-hero.webm",
    poster: "/images/posters/hero-bg3.webp",
    ...
  }
];

If you need to change a headline, a video link, or a navbar link, you edit the files in src/data/. The UI components automatically update.

8. Component Architecture (Modularity)

The code is strictly separated into Features:

  • Independence: src/features/Customers/customers.tsx handles its own logic, its own dragging functions, and its own responsive design. It doesn't depend on global JS scripts.
  • Dynamic Loading: In page.tsx, features are loaded using next/dynamic (e.g. loading: () => <div className="animate-pulse">). This means JavaScript for the footer or bottom sections isn't downloaded until the user scrolls down, making the site incredibly fast.

9. Practice path (do this in order)

  1. Open src/app/page.tsx and see how the page is just a stack of components.
  2. Open src/data/hero.ts, change a headline text, save, and watch it instantly update in the browser.
  3. Open src/features/Hero/hero.tsx and trace how it maps over HERO_SLIDES.
  4. Open src/app/globals.css to see the Tailwind CSS setup and custom Oklch color variables defining the theme.
One sentence summary: Next.js App Router (in src/app) handles the URLs, Feature components (in src/features) build the UI using Tailwind CSS, and Content (in src/data) keeps everything data-driven and easy to update.
